# 功能归档 (Feature Archive)

当用户输入 "功能归档 [X]"、"补功能文档 [X]"、"生成功能上下文 [X]" 或 "feature archive [X]" 时，触发此规则。

## 角色
你是一个 **高级技术架构师 (Senior Technical Architect)**。你的任务不是单纯回顾本次对话，而是基于**现有代码 + 本次新增改动**，为一个既有功能补齐一份高密度的技术上下文归档。

## 目标
不要写成用户说明书。要写给**接手的开发者/AI**，让对方快速理解一个“原本就存在但文档缺失”的功能，并且知道这次迭代新增了什么、为什么这么改、后续应该从哪里接着做。

## 执行步骤
1. **锁定功能范围**: 明确用户要补文档的目标功能，优先识别其入口 Controller、核心 Service、关键 Entity/DTO、Mapper/XML。
2. **代码为准，不许脑补**: 你**必须**先通过 `SemanticSearch` 或 `Glob` + `ReadFile` 搜索并阅读相关源码，必要时补充查看最近改动。严禁只靠对话历史生成结论。
3. **区分“原有能力”与“本次新增”**:
   - 先说明这个功能原本怎么工作。
   - 再说明本次迭代新增/修改了什么。
   - 最后解释这些变更对后续迭代有什么影响。
4. **结构化输出**: 在 `agent-doc/reference/` 目录下创建一个新文件，命名格式建议与项目归档保持一致，为 `v{版本}_{功能模块}_context.md` (例如: `v1_workflow_engine_context.md`)。

## 文档模板 (Document Template)

```markdown
# [版本/功能] 技术上下文归档

## 1. 功能目标与业务场景 (Feature Goal & Business Context)
- 这个功能解决什么问题。
- 它属于哪个业务流程，主要用户场景是什么。
- 如果这是一个老功能，简述它在系统中的历史定位。

## 2. 系统架构与执行链路 (System Architecture & Flow)
- **关键组件**: 列出 Controller / Service / Mapper / Entity / 外部依赖。
- **交互流程**: 使用 Mermaid `sequenceDiagram` 或 `flowchart` 描述从入口到落库/返回结果的完整流程。
- **数据流向**: 说明请求数据、状态数据、结果数据分别如何流动。

## 3. 代码拓扑与关键文件 (Code Topology)
- **入口**: `Controller`、定时任务、消息监听器、事件入口等。
- **核心逻辑**: `Service`、领域逻辑类、策略实现类。
- **数据契约**: `DTO/VO/Entity`、Mapper、XML、缓存 Key、事件体。
- **强相关文件列表**: 给出准确相对路径，便于下一个 AI 直接加载。

## 4. 原有实现机制 (Existing Implementation)
- 说明该功能在本次迭代前的核心实现方式。
- 解释复杂逻辑、状态流转、参数解析、并发处理、缓存策略或降级策略。
- 指出会读写哪些表、缓存、外部服务。

## 5. 本次迭代变更 (Changes In This Iteration)
- **新增能力**: 今天新增了什么功能、接口、字段、配置或流程。
- **修改点**: 改了哪些原有逻辑，为什么改。
- **影响面**: 哪些上下游模块、数据结构、状态流、兼容性会受到影响。

## 6. 接口与数据契约 (Interfaces & Data Contracts)
- **API 定义**: 新增/修改的接口入参、出参。
- **数据结构**: 核心 DTO/VO/Entity 字段变化。
- **数据库变更**: 表、字段、索引、枚举值、状态值变化。

## 7. 风险、遗留问题与接手建议 (Risks & Handoff Notes)
- **已知问题 / TODO**
- **边界条件 / 异常处理**
- **下一个迭代者最应该先读的文件和原因**
- **待确认项**: 任何无法从代码中完全确认的地方必须明确标记。
```

## 注意事项
- **文档定位**: 这是“功能级上下文归档”，不是随手总结，也不是纯架构漫谈。
- **Source of Truth**: 一切结论必须来自真实源码，必要时结合最近改动一起分析。
- **对比视角**: 必须写清楚“原来如何工作”与“这次改了什么”。
- **代码引用**: 提到代码时，必须使用精确的文件相对路径。
- **准确性**: 不确定就写“待确认”，不要编。
