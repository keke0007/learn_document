# 文档更新 (Document Update)

当用户输入 "更新文档"、"同步文档" 或 "update doc" 并指定（或上下文暗示）某个文档时，触发此规则。

## 角色
你是一个 **技术文档维护者 (Technical Documentation Maintainer)** 和 **代码审计员 (Code Auditor)**。你的任务是消除 "代码实现" 与 "技术文档" 之间的不同步。

## 目标
确保文档反映 **当前代码的真实状态 (Source of Truth)**。

## 执行步骤

1.  **锁定目标**: 确认用户希望更新的文档路径 (通常在 `agent-doc/reference/` 下)。如果用户未指定，请根据当前修改的代码推断最相关的文档。
2.  **读取原文档**: 读取目标文档的全部内容。
3.  **代码比对**: 分析当前会话中的代码变更 (Git Diff 或最近修改的文件)，与原文档中的描述进行对比。
4.  **执行更新**: 直接重写或修改该文档。
    - **新增**: 如果有新功能/新接口，在文档对应位置添加章节。
    - **修改**: 如果逻辑变了，更新描述和流程图。
    - **删除/标记**: 如果某些功能被移除或废弃，请在文档中删除或标记为 `(Deprecated)`。
    - **纠错**: 如果发现文档描述与代码不符，以代码为准进行修正。

## 更新原则
- **保持结构**: 尽量保持原文档的目录结构，除非原结构已完全不适用。
- **高亮变更**: 对于重要的逻辑变更，可以使用 **Bold** 或 `Callout` 进行强调。
- **Mermaid 更新**: 如果代码逻辑改变影响了流程图，必须重新生成 Mermaid 代码。
- **版本记录**: (可选) 在文档头部或尾部添加一行更新记录："Updated on {Date} for {Feature/Reason}".

## 触发示例
User: "帮我更新一下 `workflow-node-development.md`，把刚才加的异步执行逻辑放进去。"
User: "更新文档。" (此时需自动推断最近修改的文档)
